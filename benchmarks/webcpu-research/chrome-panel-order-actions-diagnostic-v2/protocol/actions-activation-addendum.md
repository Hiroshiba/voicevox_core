# Prospective Actions activation clarification

The sealed revision-3 scientific plan and its numerical, fixture, schedule,
statistics, memory, phase and safety gates are unchanged. This document describes
execution plumbing needed to turn the already reviewed disabled source into a
portable, separately authorized one-attempt Actions program. Preparation of this
source executes no compiler, runtime payload, browser, model or CI job.

1. The local compile and independent static emitted review have passed. All ten
   final arm JS/Wasm files retain their exact admitted bytes. Removing source-only
   guards from the three host assets is an explicit source delta and separate
   manifest binding; the original thirteen-file receipt remains immutable.
2. The immutable source-release commit and the later request-trigger commit are
   distinct. The source manifest and independent review bind the former's actual
   bytes. The actual Actions event commit and job identity are recorded separately
   and carried unchanged; they are not falsely equated with the release commit.
3. One attempt uses the fixed `RUNNER_TEMP/panel-order-screen-attempt` root, an
   exclusive retained claim and the first Actions run attempt only. Explicit child
   descriptors and consumed leases bind the admitted parent generation, job,
   source, request, phase, target and arguments. These are per-job controls, not a
   claim to a remote cross-job token-consumption service. A later request still
   needs explicit root authorization and is not an automatic retry.
4. The initial psutil helper cannot be production-observed by psutil before it
   exists. A bounded standard-library acquisition and safe extraction of its exact
   official pinned wheel establishes that observer without a subprocess. Setup,
   checkout and this bootstrap consume the original provisioning and outer-job
   clocks. Production ownership starts only after complete helper verification.
5. The activation helper closure includes `typing_extensions`, imported by pyee,
   and pins the actually used derived browser helpers rather than stale donor
   bytes. These are import/provenance corrections, not arithmetic changes.
6. Portable SDK/dependency configuration paths are regenerated under the owned
   root. Available official archive hashes and exact compiler/tool/source hashes
   are enforced. Where an official SDK archive's historical whole-byte hash is
   unavailable, the reviewed recipe states that limitation, bounds one official
   acquisition and records its bytes before admitting the prepinned tool files.
   This never substitutes for the mandatory exact ten-file final rebuild gate.
7. Chrome follows the already approved once-per-CI-attempt acquisition policy:
   predetermined official version/platform/source/helper, complete acquired
   archive/executable/support identity before any launch, and unchanged retained
   bytes across probes, qualification, timing and transition. Missing identity or
   any mismatch terminates without substitution, repeat acquisition or rebuild.

8. The public artifact is an atomic, aggregate-32-MiB pair of scalar JSON files.
   Context-specific field/type/vector rosters retain all valid call evidence and
   quarantine malformed records without losing attempted positions. Acquisition
   metadata and compact ownership/resource summaries remain auditable; raw argv,
   host identifiers and tensors are excluded. Export is always unreviewed and is
   revoked if subsequent finalization fails. No additional operator calls result.

   Playwright 1.63 source, with inert excerpts retained. Existing default switches
   are preserved; only the admitted executable and bounded owned profile suffix

   overrides. No browser probe or learned normalization supplies expected flags.

The source-only mock suite and independent source review establish source-stage
properties only. Cross-host byte reproduction and all 330 qualification calls
remain unperformed. A complete passing qualification receipt, ownership/resource
