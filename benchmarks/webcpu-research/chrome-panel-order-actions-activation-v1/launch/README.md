# Reviewed, root-authorized Actions activation source

This separate source revision implements execution after an explicit root GO and
matching independent source review. No execution, installation or acquisition was
performed to prepare it. The frozen original panel and local compile sources stay
unchanged. Importing a module, an Actions environment variable or a CLI switch
alone grants no authority.

## Authority and paths

The sole root CLI is pinned CPython 3.12, `-B -I`, absolute `tools/program.py
--actions --request GO --source-review REVIEW --source-manifest MANIFEST --work
WORK --clock CLOCK`. All path arguments are absolute. WORK is exactly
`RUNNER_TEMP/panel-order-screen-attempt`, claimed exclusively before acquisition
and retained on success or failure. First Actions run attempt only. The root GO
has issuer `root`, the exact conditional scope, immutable source/review hashes
and unchanged phase budgets. The independent review schema is
`panel-actions-source-review-v1`, status PASS, independent true, scope
`one_same_job_330_then_conditional_600`; it binds canonical source inventory,
local emitted admission and the separately activated three-host-file manifest.

Canonical source identity is SHA256 of sorted compact JSON
`{relative_name:{bytes,sha256}}`, supplied by `chrome-panel-source-seal-v1`.
Actual executing bytes and complete source directory rosters are checked before
provisioning. The immutable source-release commit is provenance; the later
request-only trigger commit is separately observed and retained. The workflow
checks out that source release explicitly. This is per-job, per-attempt
containment, not a cross-job globally consumed-token service.

A private descriptor binds source/request/review, fixed work root, job, boot,
root PID/start generation and clocks. Every isolated ownership/phase/operator
child must validate it again and consume one exact target/argv/phase lease.
Only the fixed child target roster is admitted. Leases cannot be replayed or
extended after issuance. Phase order is provision, compile, qualification,
timing. The parent remains alive while its children run. Already imported helper
or source-package shadowing is terminal; no environment-based activation exists.

## Fresh provisioning

`bootstrap-inputs.json` records exact official URLs, sizes, archive pins where
available, extraction limits, source patches, native command templates, source
closure and SDK critical-file identities. `bootstrap_fetch.py` acquires once,
uses no ambient proxies/retries/mirrors, validates bounded complete archives,
and extracts safe regular members plus only explicitly pinned links. Direct
stdlib acquisition/extraction of the exact psutil wheel solves the initial
observer dependency. Its entire 150-second window includes a 120-second work
allowance and 30-second cleanup reserve, and consumes provisioning time. There
is no claim that production psutil ownership observation existed beforehand.
Complete psutil package bytes are checked before its first native import.

The remaining provisioning runs inside the production-owned, continuously
observed phase. It reconstructs SDK4.0.8, the pinned runtime and ORT source,

three generated ONNX header targets, and the accepted baseline. Baseline members
514 and757 alone change; all other1436 payloads and order are proved. Original
source/header closure, generated headers, exact compile/include command and
control/candidate IR proofs are checked. No ORT model or emitted Wasm is run.
Host `/usr/bin/make` is an Ubuntu24.04 prerequisite whose complete ELF bytes are
observed once and pinned in-job; no whole OS tree equivalence is claimed.

SDK Node/tools archive hashes are acquired once from the exact official pinned
release URLs; exact compressed sizes have retained historical download-log
provenance. The complete15,673-file non-cache execution/header roster, critical tool
bytes and logical source/header closure are prepinned. Generated cache bytes
are separately frozen within the job. This does not establish equality to the complete historical SDK
cache tree. All fresh retained SDK/dependency/baseline bytes are snapshotted and
verified before/after final compilation, with a frozen cache and exact link roster.
Any mismatch is terminal. In-job locks never replace final exact asset admission.

The 8GiB observed provisioning-tree ceiling, 4GiB free-space reserve and 12GiB
