This sibling runner releases only the predeclared 27-call original/rebuilt/candidate ON screen after two manual reviews of actual Chrome capture run37993934600. `release_contract.json` is SHA-pinned by `release_gate.py`, includes the manual-review document hash, exact source archive/JS/Wasm/callback identities, original ON FP32/PCM/WAV reference, pinned engine, and 27-call scope. Before timing, fresh runtime/alias/output/activation gates run and must match the reviewed evidence. No raw capture or native profiler runs in this timing process. Three fresh process sets × three matched rounds × three conditions; nine paired observations per control. Five warmups per condition, repeated before/after exact checks, idle interval, original sentinels and boundary process/host resource observations are retained. No high-frequency sampler. All measured rows are retained, including faults. Fault/order/leave-one-set-out summaries are descriptive sensitivities, never selective primary deletion. Available memory below 1 GiB stops the run. Before measurement, the release adds whole-run quality criteria: complete monotonic resource counters and stable process identities, no target/host swap growth or activity, available memory at least 1 GiB, and every end/start sentinel ratio in the inclusive [0.90,1.10] interval. Quality failures do not delete observations: a completed run retains all 27 rows but is labeled inconclusive_invalid_quality with performance_claim_allowed=false. No headline gain/adoption claim is permitted from such a run.
